# Dual-Screen Competition Dashboard

## Why

当前的赛事大屏（`Screen.tsx`）将统计图表、排行榜、日志等信息压缩在单页面多面板网格中。在大型赛事指挥场景中，主办方通常使用多个显示器分别展示不同维度的信息：一个屏幕专注于统计图表和态势感知，另一个屏幕专注于实时滚动的提交日志，避免信息过载，提升可读性和视觉冲击力。

## What

在现有大屏页面基础上，新增双屏展示模式：
- **图表屏**：占据整个显示器，展示赛事统计图表（雷达图、趋势图、排行榜、进度等），无滚动条，全屏自适应
- **日志屏**：占据整个显示器，展示滚动日志（提交流水、事件动态），自动滚动，无滚动条，全屏自适应
- 用户可在全屏模式下通过快捷键或界面按钮切换两个屏幕
- 通过 URL 参数（如 `?view=charts` / `?view=logs`）区分展示视图
- 两个页面共享同一数据源（SignalR 实时推送 + SWR 轮询），各自独立渲染

## Constraints

- MUST 支持多显示器场景：同一 URL 在不同窗口/标签页打开时，各自独立展示
- MUST 全屏后自适应显示器大小，内容铺满全屏，不出现滚动条
- MUST 保留现有单页大屏布局作为默认视图
- MUST 在测试模式（demoData）下同样可用
- 不修改后端 API，仅在前端实现视图路由

## Non-Goals

- 不在后端增加多屏同步或屏幕管理接口
- 不做第三方推流/投屏集成
- 不修改现有单页大屏的布局与样式

## Open Questions

- 是否需要 WebSocket 级别的跨屏同步（如日志屏的滚动位置），还是两个屏各自独立消费同一 SignalR 流即可
- 图表屏是否需要精简版（去除 header 等装饰元素）以最大化展示面积
